# Ohio Childcare: Incident, Injury, and Illness Documentation Workflow (2026)

This post is informational and operational, not legal advice. Confirm exact requirements for your program type in the Ohio Administrative Code (OAC) and any current ODJFS guidance.

## Why this is a high-risk area in inspections

Most findings are not because something happened, but because the program could not prove:

- what happened
- when it happened
- who responded
- what was communicated to guardians
- where the record is stored

## The minimal workflow that stays inspection-ready

Use the same steps every time, even for “minor” events:

1. **Stabilize first:** child safety, supervision coverage, first aid as needed.
2. **Capture facts (not opinions):** time, location, who witnessed, what was observed.
3. **Actions taken:** first aid, separation, cleaning, monitoring, escalation.
4. **Guardian communication:** who was contacted, when, and how (and if unsuccessful, attempts).
5. **Director review:** same-day or next-business-day review and sign-off.
6. **File it once:** one canonical location, consistent naming, consistent retention.

## What to include on the form (checklist)

- Child name + classroom/group
- Date/time and exact location
- Staff present and witness names
- Description using observable language
- Body map or injury description when relevant
- Actions taken and outcomes
- Guardian notification details
- Follow-up plan (monitoring, medical referral, environmental fix)

## Common mistakes that create compliance exposure

- “Verbal only” notification with no record
- Missing times (start, event, notification)
- Vague wording (“child fell”) with no location/context
- Multiple versions stored in different places
- No supervisor/director review

## What to do this week (15 minutes)

- Create a standard naming convention: `INCIDENT_YYYY-MM-DD_Last_First_Classroom.pdf`
- Decide one storage path (and lock it): `Incidents/YYYY/Month/`
- Add a weekly review step: “Any incident missing guardian notification?”
